API Reference

Every type and function of Shearlets, including the names it re-exports from AbstractMultiscaleTransforms and MultiscaleFilterBanks.

Module

Shearlets.Shearlets — Module
Shearlets

Discrete shearlet transforms of images and volumes, translation invariant and computed on the DFT grid.

Quick reference

FunctionDescription
analyze / synthesize (and ! forms)Transform and its inverse; a streaming form of each
make_workspaceMasks, plans and buffers for repeated transforms
subband_layout / nsubbands / subbandWhat each subband is, and where it is in the coefficients
shearlet_spectraThe frequency responses, for inspection

The verbs and accessors are those of AbstractMultiscaleTransforms, re-exported here; every shearlet system is an AbstractMultiscaleTransform.

Shearlet systems:

  • BandlimitedShearlets: Häuser & Steidl's FFST, band-limited Meyer shearlets, a Parseval frame;
  • NSSTShearlets: Easley, Labate & Lim's nonsubsampled shearlet transform, an à trous pyramid with shearing filters (2-D data only);
  • CompactShearlets: ShearLab 3D's compactly supported digital shearlets, with dual-frame reconstruction.

Every system is a set of real, point-symmetric masks on the DFT grid, so a transform is one FFT plus one inverse FFT per subband. The coefficients of x form one array of size (size(x)..., nsubbands).

Shearlet systems

Shearlets.ShearletSystem — Type
ShearletSystem <: AbstractMultiscaleTransform

Abstract type of the shearlet systems: a description of the frame that does not depend on the data size. The masks themselves are built for one size and element type by make_workspace.

Subtypes: BandlimitedShearlets, NSSTShearlets, CompactShearlets.

source
Shearlets.BandlimitedShearlets — Type
BandlimitedShearlets(; scales = 0, smooth = false, alpha = 1)

The band-limited cone-adapted shearlet system of Häuser & Steidl's Fast Finite Shearlet Transform (FFST): Meyer-type windows on the full DFT grid, a Parseval frame whose inverse is its adjoint. Works on 2-D and 3-D data (cones become the three pyramids around the axes).

  • scales: number of scales J (0 picks ⌊log₂(min(size)) / 2⌋). Scale j has s = 2^(j-1) shears per side of each cone; in 2-D that is 4s shearlets, two of them seam shearlets glued across the cones.
  • smooth: use the tensor-product lowpass of Guo & Labate's construction, which makes the seam shearlets smooth (and better localized in space) at the price of a less cone-aligned lowpass.
  • alpha: the anisotropy of α-shearlets, 0 ≤ α ≤ 2: s = round(2^((2-α)(j-1))) shears per side. α = 1 is parabolic scaling (shearlets), α = 2 keeps one shear per side at every scale (wavelet-like), α → 0 approaches ridgelets.

Every subband has the size of the input; real input gives real subbands. show prints the keyword call that rebuilds the system.

Examples

julia> using Shearlets

julia> sys = BandlimitedShearlets(scales = 2)
BandlimitedShearlets(scales = 2, smooth = false, alpha = 1.0)

julia> nsubbands(sys, (64, 64))   # lowpass, 4 shearlets at scale 1, 8 at scale 2
13

References

  1. S. Häuser and G. Steidl, "Fast Finite Shearlet Transform: a tutorial",

  2. K. Guo and D. Labate, "The Construction of Smooth Parseval Frames of Shearlets", Mathematical Modelling of Natural Phenomena, 8(1):82–105, 2013. doi:10.1051/mmnp/20138106

Shearlets.NSSTShearlets — Type
NSSTShearlets(; direction_levels = [3, 3, 4, 4], filter_size = nothing, pyramid = CDF97)

The nonsubsampled shearlet transform (NSST) of Easley, Labate & Lim (2008): a nonsubsampled Laplacian pyramid with length(direction_levels) levels, each split by shearing filters into 2^direction_levels[j] directional subbands (scale j = 1 is the coarsest). Every subband has the size of the input. The system is defined for 2-D data only; other dimensions throw an ArgumentError.

  • direction_levels: log₂ of the number of directional subbands per scale, coarse to fine (any iterable of integers), each at least 2: a scale with d levels has 2^(d-2) shears per side of each cone and two seam subbands glued across the cones.
  • filter_size: the side L of the spatial shearing filters, per scale (a vector) or for all scales (an integer). Larger filters resolve directions better near the origin; smaller ones are more local. 0 samples the windows on the image's own DFT grid (the frequency-domain variant). L is clamped to each side of the image, so an L at least as large as both sides is the frequency-domain variant too. The default is 32 for the scales coarser than the two finest, which use 16.
  • pyramid: the 1-D filter pair of the à trous pyramid; it must be symmetric with an odd number of taps.

The frame is not tight: synthesize sums the directional subbands of each level and inverts the pyramid.

show prints the keyword call that rebuilds the system, without pyramid when it is CDF97. A pyramid filter of more than 32 taps prints as its size and element type, which does not parse back; the text/plain display adds its taps.

Examples

julia> using Shearlets

julia> sys = NSSTShearlets(direction_levels = [2, 3], filter_size = 0)
NSSTShearlets(direction_levels = [2, 3], filter_size = [0, 0])

julia> nsubbands(sys, (64, 64))   # lowpass, 2^2 and 2^3 directional subbands
13

References

  1. G. Easley, D. Labate, and W.-Q. Lim, "Sparse Directional Image Representations Using the Discrete Shearlet Transform", Applied and Computational Harmonic Analysis, 25(1):25–46, 2008. doi:10.1016/j.acha.2007.09.003

Shearlets.CompactShearlets — Type
CompactShearlets(; scales = 4, shear_levels = ceil.(Int, (1:scales) ./ 2), qmf, fan)

The compactly supported digital shearlets of ShearLab 3D (Kutyniok, Lim & Reisenhofer, 2016), without subsampling: shift invariant, every subband the size of the input. Spatially compact filters, at the price of a frame that is not tight — the inverse uses the dual filters.

  • scales: number of scales J, coarse to fine.
  • shear_levels: per scale (any iterable of integers) the level d: shears k = -2^d, …, 2^d in each cone, 2(2^(d+1) + 1) subbands per scale. The default is parabolic scaling.
  • qmf: the 1-D lowpass of the quadrature mirror pair (symmetric, odd length); the highpass is its modulation (-1)^n h[n]. The default is ShearLab's 9-tap maximally flat filter.
  • fan: the 2-D fan filter P as a matrix of taps with the origin at its center, passing the horizontal fan |ω₂| < |ω₁|; the default is the maximally flat fan filter of order 4 of da Cunha, Zhou & Do (2006).

The two cones overlap at the seam lines (|k| = 2^d in both), as in ShearLab.

show prints the keyword call that rebuilds the system, without qmf and fan when they are the defaults. A filter of more than 32 taps prints as its size and element type (fan = <9×9 Matrix{Float64}>), which does not parse back; the text/plain display adds its taps.

On 3-D data the cones are the three pyramids around the axes and a shearlet has a shear (k₁, k₂) against each of the other two axes, 3(2^(d+1) + 1)² subbands per scale (ShearLab 3D's Definitions 3.3–3.4).

Examples

julia> using Shearlets

julia> sys = CompactShearlets(scales = 2);

julia> nsubbands(sys, (64, 64))   # lowpass, 10 subbands per scale
21

References

  1. G. Kutyniok, W.-Q. Lim, and R. Reisenhofer, "ShearLab 3D: Faithful Digital Shearlet Transforms Based on Compactly Supported Shearlets", ACM Transactions on Mathematical Software, 42(1):5, 2016. doi:10.1145/2740960
  2. W.-Q. Lim, "Nonseparable Shearlet Transform", IEEE Transactions on Image Processing, 22(5):2056–2065, 2013. doi:10.1109/TIP.2013.2244223

Shearlets.ShearletIndex — Type
ShearletIndex{M}

Where a subband sits in a shearlet system on an N = M + 1-dimensional grid:

  • scale: 0 for the lowpass, else 1, …, J from coarse to fine;
  • cone: 0 for the lowpass, else the axis the frequencies of the subband are largest along (1: the horizontal cone |ω₂| ≤ |ω₁| of a matrix, whose rows are axis 1; 2: the vertical cone);
  • shear: the shear of each of the other M axes against cone.

A subband of cone c and shear k at scale j collects the frequencies with ω_e / ω_c ≈ -k / 2^(j-1) for the other axes e. Where a shear reaches the seam between two cones (|k| = 2^(j-1) for band-limited shearlets), the subband is glued across the seam and listed under the lower cone.

ShearletIndex(; scale, cone, shear)

The index with these fields, M = length(shear); this is also the form show prints. subband_layout(system, dims) lists the indices of a system's subbands.

Examples

julia> using Shearlets

julia> layout = subband_layout(BandlimitedShearlets(scales = 1), (32, 32));

julia> layout[1], layout[2]
(ShearletIndex(scale = 0, cone = 0, shear = (0,)), ShearletIndex(scale = 1, cone = 1, shear = (-1,)))

julia> islowpass(layout[1])
true

Shearlets.shearlet_spectra — Function
shearlet_spectra(system, [T = Float64,] dims; synthesis = false) -> Array{T}

The frequency responses of all subbands of system, of the real element type T, on the full, unshifted DFT grid of a dims array: an array of size (dims..., n), in subband_layout order. Subband i of x is real(ifft(spectra[.., i] .* fft(x))).

With synthesis = true, the masks the inverse applies instead: x is real(ifft(sum(spectra .* fft(subbands)))). For a Parseval system the two are equal. dims has 2 or 3 entries (2 for NSSTShearlets).

Examples

julia> using Shearlets

julia> spectra = shearlet_spectra(BandlimitedShearlets(scales = 1), (32, 32));

julia> size(spectra)
(32, 32, 5)

julia> sum(abs2, spectra; dims = 3) ≈ ones(32, 32)   # a Parseval frame
true

Transforms

The verbs of AbstractMultiscaleTransforms, for shearlet systems. Every form also takes a workspace in place of the system: analyze(ws, x), analyze!(c, ws, x), synthesize(ws, c), synthesize!(x, ws, c), analyze(f, ws, x) and synthesize!(f, x, ws).

AbstractMultiscaleTransforms.analyze — Method
analyze(system::ShearletSystem, x; workspace = nothing, threaded = nothing) -> AbstractArray

Shearlet transform of x: an array of size (size(x)..., n) whose slice i along the last axis (subband(system, c, i)) is the subband subband_layout(system, size(x))[i] (the lowpass first). The transform is invariant under circular shifts of x; real input gives real subbands, and complex input is transformed as its real and imaginary parts, so analyze(system, complex.(a, b)) == complex.(analyze(system, a), analyze(system, b)) exactly. The subbands are computed in parallel unless threaded = false (nothing threads). The data, and every coefficient and output array of the transforms below, must be indexed from 1 (an ArgumentError otherwise).

workspace is a ShearletWorkspace for this system, element type and size; device data needs one (see make_workspace). Without one, masks and plans are built for the call.

Examples

julia> using Shearlets, Random

julia> x = randn(Xoshiro(1), 64, 64);

julia> c = analyze(BandlimitedShearlets(scales = 2), x);

julia> size(c)
(64, 64, 13)

julia> sum(abs2, c) ≈ sum(abs2, x)   # a Parseval frame
true

AbstractMultiscaleTransforms.analyze — Method
analyze(f, system::ShearletSystem, x; workspace = nothing, threaded = nothing) -> nothing

Streaming shearlet transform: calls f(i, band) for every subband i in subband_layout order, reusing one buffer between calls, so the coefficient set is never held at once. band is valid only until f returns — copy or reduce it there. The subbands are computed one at a time: f is called once per subband, in that order, from the calling task. threaded has no effect (it is accepted for the common interface).

source
AbstractMultiscaleTransforms.synthesize! — Method
synthesize!(f, x, system::ShearletSystem; workspace = nothing, threaded = nothing) -> x

Streaming inverse into x: f(i) must return subband i (in subband_layout order) as an array of size size(x). The subbands are consumed one at a time: f is called once per subband, in subband_layout order, from the calling task, and each result is read before the next call, so f may reuse one buffer. threaded has no effect (it is accepted for the common interface).

Shearlets.ShearletWorkspace — Type
ShearletWorkspace{Td, Tf, N} <: AbstractTransformWorkspace

Masks, FFT plans and buffers of a shearlet system at one data size and element type Td (filters in Tf = real(float(Td))). Build with make_workspace and pass it as workspace to analyze / synthesize to keep repeated calls out of the allocator, or call the verbs on the workspace alone (analyze(ws, x), synthesize!(x, ws, c), ...). transform(ws) is the system, eltype(ws) the data element type Td and size(ws) the data size.

A workspace holds scratch buffers, so it must not serve two transforms at the same time; it threads internally instead, over at most the tasks it was built with.

source
AbstractMultiscaleTransforms.make_workspace — Method
make_workspace(system::ShearletSystem, T::Type{<:Number}, dims::Dims;
               flags = FFTW.MEASURE, tasks = nothing, tune = false, prewarm = false) -> ShearletWorkspace

Build the masks, buffers and FFT plans of system for host data of element type T (real or complex; integers count as float(T)) and size dims.

  • flags: the FFTW planner flags of the FFT plans (an integer).
  • tasks: the most tasks a call with the workspace threads its subbands over, each with its own FFT buffers; nothing is one per Julia thread, 1 a serial workspace (whatever threaded a call passes). At least 1.
  • tune: ignored on the host (it tunes device workspaces).
  • prewarm: run one analysis and one synthesis on zeros at construction, so that the first call does not compile. It costs a transform and, meanwhile, a full coefficient array.

AbstractMultiscaleTransforms.make_workspace — Method
make_workspace(system::ShearletSystem, x::AbstractArray;
               flags = FFTW.MEASURE, tasks = nothing, tune = false, prewarm = false) -> ShearletWorkspace

The workspace of system for data like x: its element type, size and device. For a host array this is make_workspace(system, eltype(x), size(x); flags, tasks, tune, prewarm).

For a device array (a CuArray, say) the masks are built on the host and moved to the device by the Adapt extension; the FFT plans are the device FFT library's. A device workspace transforms its subbands in chunks, one batched FFT per chunk, with a chunk size that by default follows from the grid size. tune = true measures instead (MultiscaleFilterBanks.mask_bank_tune): it times one subband at a time and chunks of powers of two subbands, each with the synthesis chunked or not, on a forward and an inverse transform, and keeps the default unless another is 5% faster. Tuning holds a coefficient array and the stacks of one more chunk size on the device meanwhile; the transform itself is unchanged. Tuning pays off mainly for NSSTShearlets; for the other systems the default chunking is usually as fast, and tuning only lengthens the construction. On the host tune does nothing: a host workspace threads over subbands instead.

On a device flags and tasks are ignored (tasks is still checked to be at least 1): the device FFT library plans the FFTs, and the device engine runs in one task. prewarm = true runs one analysis and one synthesis on zeros on the device, after the tuning.

ws = make_workspace(system, CuArray{Float32}(undef, 256, 256); tune = true)

AbstractMultiscaleTransforms.AbstractMultiscaleTransforms — Module
AbstractMultiscaleTransforms

The interface shared by multiscale transform packages (contourlets, surfacelets, shearlets, wavelets, ...): transform objects, the verbs analyze and synthesize, reusable workspaces, and subband access on array-valued coefficients. It defines no transform of its own.

A package implementing a transform depends on this one, subtypes AbstractMultiscaleTransform, adds methods to the verbs and accessors, re-exports them, and checks its types with AbstractMultiscaleTransforms.Testing.test_transform.

source
AbstractMultiscaleTransforms.AbstractMultiscaleTransform — Type
AbstractMultiscaleTransform

Supertype of transform objects. A transform is an immutable value that holds every parameter of the decomposition (number of scales, directions per scale, filters, ...) and nothing that depends on the data's size or element type, so one transform serves arrays of any admissible size. Two transforms with equal parameters are == and have equal hash.

An implementation defines, for its transform type T:

RequiredPurpose
analyze!(c, t::T, x; workspace, threaded)analysis into preallocated coefficients
synthesize!(x, t::T, c; workspace, threaded)synthesis into a preallocated array
similar_coefficients(t::T, x)uninitialised coefficients for data like x
subband_layout(t::T, dims)one descriptor per subband, lowpass first
subband(t::T, c, i)subband i of c, a view
OptionalDefault
analyze(t::T, x; ...)analyze!(similar_coefficients(t, x), t, x; ...)
synthesize(t::T, c; ...)synthesize! into an array of size signal_size(t, c)
signal_size(t::T, c)needed by the default synthesize, except for SubbandVector coefficients
make_workspace(t::T, T, dims; ...) / make_workspace(t::T, x; ...)a DefaultWorkspace
nsubbands(t::T, dims)length(subband_layout(t, dims))
analyze(f, t::T, x; ...), synthesize!(f, x, t::T; ...) with supports_streaming(t::T) = truenot supported

Every implementation also follows these conventions; AbstractMultiscaleTransforms.Testing.test_transform checks most of them:

  • The transform holds every parameter, is immutable, and two transforms with equal parameters are == and have equal hash.
  • Every verb accepts the keywords workspace and threaded. A method that receives a workspace checks it with check_workspace before using it.
  • Wrong input throws before any work: a DimensionMismatch for a wrong size, an ArgumentError for another wrong argument, each with a message.
  • Complex data is transformed as its real and imaginary parts, so that analyze(t, x + im * y) ≈ analyze(t, x) + im * analyze(t, y) for real x and y.
  • The implementing package lists the interface's exported names in its own export, so that using it is enough.

AbstractMultiscaleTransforms.AbstractTransformWorkspace — Type
AbstractTransformWorkspace

Supertype of workspaces: everything a transform precomputes for one data size, element type and array type (filter responses, FFT plans, scratch buffers), so that repeated calls allocate little or nothing. Build one with make_workspace.

A workspace answers transform, eltype (the data element type) and size (the data size). It holds scratch buffers, so it serves one call at a time; give each task its own. A call whose transform, size or element type does not match the workspace throws (see check_workspace).

A workspace can stand in for its transform: analyze(ws, x) is analyze(transform(ws), x; workspace = ws), and likewise for the other verbs.

A transform that has plans or buffers to reuse defines its own subtype, with methods for transform, eltype and size, and make_workspace methods for make_workspace(t, T, dims) and, if the workspace depends on the array type (a GPU array, say), for make_workspace(t, x). Both accept the shared keywords listed there. A transform without one gets a DefaultWorkspace.

AbstractMultiscaleTransforms.SubbandVector — Type
SubbandVector(data::AbstractVector, layout::SubbandLayout)

Coefficients made of subbands of different sizes, stored one after another in the single vector data (a host Vector or a device vector) and presented as an AbstractVector of all coefficients. subband(c, i) is a reshaped view of subband i.

Broadcasting, similar, copyto!, fill!, ==, isapprox, mapreduce (sum, maximum, ...) and LinearAlgebra.dot/norm/axpy!/axpby!/ rmul!/lmul! act on data directly, so they need no scalar indexing on a device and keep the layout. Operands of one operation must share a layout. Adapt.adapt moves the storage (a method defined once Adapt is loaded, as every GPU array package does).

julia> using AbstractMultiscaleTransforms

julia> layout = SubbandLayout([(2, 2), (4, 4)], (4, 4));

julia> c = SubbandVector(collect(1.0:20.0), layout);

julia> subband(c, 1)
2×2 reshape(view(::Vector{Float64}, 1:4), 2, 2) with eltype Float64:
 1.0  3.0
 2.0  4.0

julia> d = 2 .* c .+ 1;

julia> d isa SubbandVector && subband(d, 1)[1] == 3.0
true

AbstractMultiscaleTransforms.Testing.test_transform — Function
test_transform(t, x; rtol, wrong_size = nothing, exact_real_linear = false)

Needs the Test standard library loaded (using Test), which defines the method.

Run the interface's conformance tests for transform t on data x, inside a @testset:

  • analyze returns an array, whose nsubbands(t, size(x)) subbands cover all of its entries; synthesize reconstructs x (to rtol);
  • analyze!/synthesize! into preallocated arrays, the workspace (make_workspace) and workspace-only forms, and threaded = true/false give the same results;
  • both make_workspace forms accept the shared keywords flags, tasks, tune and prewarm, the workspace built with them gives the same results, and an unknown keyword throws a MethodError;
  • the transform equals its copy, with an equal hash;
  • broadcasting, similar, copyto!, norm and dot work on the coefficients;
  • the streaming forms, if supports_streaming(t), give the same subbands and reconstruction;
  • a workspace for another size (wrong_size, when given) is rejected;
  • for complex x, the transform is real-linear: analyze(t, x) ≈ complex.(analyze(t, real(x)), analyze(t, imag(x))), exactly (==) when exact_real_linear; each side runs through a workspace built once, so that FFT planning between calls cannot change the rounding.

MultiscaleFilterBanks.FilterPair — Type
FilterPair(h::AbstractVector, g::AbstractVector)
FilterPair{T}(h, g)

A 1-D biorthogonal filter pair holding an analysis (h) and synthesis (g) low-pass filter vector. Both filters are stored as coefficient vectors whose center tap is at index ceil(Int, length/2) (1-based Julia indexing). T <: AbstractFloat is the element type, by default float of the promoted element types of h and g; the fields h and g are ReadOnlyTaps. Empty filters, and filters not indexed from 1, throw an ArgumentError.

Give odd, symmetric filters, so that the pyramid does not shift the image. By the convention of CDF97, h has DC gain 1 (its taps sum to 1) and g has DC gain 2, which compensates the ×2 upsampling of the decimated pyramid; nsp_atrous_filters halves g for the nonsubsampled one.

The pair drives the pyramid stage of the downstream transforms: h produces the coarse approximation, and g predicts the input from it, so that the difference is a bandpass (the Laplacian pyramid of Burt and Adelson [1]). Adding the prediction back reconstructs the input for any pair. Do and Vetterli [2] show that the pyramid is a frame, tight for orthogonal filters, and give a projection reconstruction that is more robust to noise than the usual one. Its nonsubsampled (à trous) form is the pyramid of the nonsubsampled contourlet transform [3].

Examples

julia> using MultiscaleFilterBanks: FilterPair

julia> spline = FilterPair([1, 2, 1] ./ 4, [1, 2, 1] ./ 2);   # linear spline pair

julia> sum(spline.h), sum(spline.g), eltype(spline)
(1.0, 2.0, Float64)

The pair copies the filters into ReadOnlyTaps vectors: it cannot be changed after it is built, and two pairs are == (and hash alike) when their taps are equal.

MultiscaleFilterBanks.CDF97 — Constant
CDF97 :: FilterPair{Float64}

The Cohen–Daubechies–Feauveau 9/7 biorthogonal filter pair [1], the irreversible wavelet filter of JPEG 2000 Part 1 [3], introduced for image coding by Antonini et al. [2]. The 9-tap analysis low-pass h is normalized to unit DC gain, the 7-tap synthesis low-pass g to DC gain 2, which compensates the ×2 upsampling of the Laplacian pyramid's synthesis step. Both are symmetric, centered at taps 5 and 4. Like every pair, it is read-only (ReadOnlyTaps).

julia> using MultiscaleFilterBanks: CDF97

julia> isapprox(sum(CDF97.h), 1.0; atol = 1e-12)
true

julia> isapprox(sum(CDF97.g), 2.0; atol = 1e-12)
true

MultiscaleFilterBanks.upsample_filter — Function
upsample_filter(h::AbstractVector, factor::Integer) -> Vector

Insert factor - 1 zeros between every tap of h. If h has frequency response $H(ω)$, the result has response $H(\text{factor}\,ω)$. h must be indexed from 1: taps are placed by position.

This is the filter upsampling of the algorithme à trous ("with holes") [1]: level $j$ of an undecimated pyramid filters with the level-1 filters upsampled by $2^{j-1}$ instead of decimating the signal, which computes the undecimated (shift-invariant) wavelet transform [2]. The nonsubsampled pyramid and the nonsubsampled directional filter banks of the downstream packages use it in the same way [3].

Examples

julia> using MultiscaleFilterBanks: upsample_filter

julia> upsample_filter([1.0, 2.0, 3.0], 2)
5-element Vector{Float64}:
 1.0
 0.0
 2.0
 0.0
 3.0

MultiscaleFilterBanks.ReadOnlyTaps — Type
ReadOnlyTaps(v::AbstractVector)
ReadOnlyTaps{T}(v::AbstractVector)

A copy of the vector v (with element type T, default eltype(v)) that cannot be written to: the filter taps of a FilterPair, so a pair, the shared CDF97 and the other filters downstream packages share cannot change after they are built. Assigning to an element throws an ArgumentError. It is an ordinary AbstractVector otherwise; copy or collect gives a mutable Vector. v must be indexed from 1 (an ArgumentError otherwise), so a filter's taps and its center tap are placed by position.

julia> using MultiscaleFilterBanks: ReadOnlyTaps

julia> t = ReadOnlyTaps([0.25, 0.5, 0.25]);

julia> sum(t), copy(t) isa Vector{Float64}
(1.0, true)

julia> t[1] = 1.0
